# 모션 플래닝 파이프라인 알고리즘 설명

대상 시스템: Unitree GO2 위에 마운트된 4-자유도(선형 이동, 롤, 벤드1, 벤드2) 연속체형 팔. 파이프라인은 "task-space 목표 → IK → RRT-Connect 전역 탐색 → 후처리(shortcut / clearance maximization) → 시간 파라미터화 → 실시간 스트리밍 실행" 6단계로 구성된다.

## 1. 좌표계 및 로봇 모델

팔의 base frame은 GO2 몸체에 고정 오프셋(mount offset)으로 부착되어 있어, world frame 기준 base pose는 GO2의 실시간 base pose(위치/자세)와 정적 마운트 오프셋의 합성(composition)으로 계산된다 (`Go2ArmMount`). 따라서 GO2가 이동/회전하면 팔의 IK/충돌 체크 좌표계도 매 호출마다 최신 base pose로 갱신되어야 한다.

관절 벡터는 $q = (l, \phi, \theta_1, \theta_2) \in \mathbb{R}^4$ (선형 변위, 롤 각도, 벤드 세그먼트 1/2 각도)로 정의되며, 각 축은 독립적인 하한/상한을 갖는다.

## 2. Task-space 목표 → 역기구학(IK)

Task-space 목표(월드 좌표 $p^*\in\mathbb{R}^3$, 선택적으로 접근 방향 $\hat{d}^*$)를 관절각으로 변환하는 2단계 파이프라인 (`solve_then_align`).

**Phase 1 — 위치 IK (감쇠 Gauss–Newton):**
4-DOF에 대해 위치 제약은 3개뿐이라 1개의 여유 자유도(redundancy)가 존재한다. 매 반복에서:
- 중심차분(central finite difference)으로 위치 자코비안 $J\in\mathbb{R}^{3\times4}$ 계산
- Tikhonov 정칙화된 정규방정식 $H = J^\top J + \lambda I,\ g = J^\top r$ 를 풀어 스텝 $\Delta q = -H^{-1}g$ 계산 (감쇠계수 $\lambda$는 고정값이며, 반복 중 재조정되지 않음 — 즉 고전적 Levenberg–Marquardt와 달리 damping-up/down 휴리스틱이 없는 **고정-감쇠 Gauss–Newton**이다)
- 백트래킹 라인서치(step-halving, 최대 6회)로 잔차 노름이 감소하는 첫 $\alpha$를 채택; 개선되는 스텝이 없으면 그 자리에서 반복을 종료(재시도 없음)
- 종료 조건: 잔차 $\|r\|$ < 위치 허용오차(1e-4 m) 또는 최대 반복(200회)

**Phase 2 — 방향 정렬 (옵션, 목표 방향이 주어졌을 때만):**
Phase 1과 구조적으로 다른 방법을 사용한다 — 다중 시드 SciPy `scipy.optimize.least_squares` (Trust-Region-Reflective). Roll 자유도를 고정한 채 나머지 3-DOF에 대해, 위치를 허용오차 이내로 유지(soft constraint)하면서 접근 방향 오차를 최소화하도록 재최적화한다. "현재 방향 유지" 모드에서는 이 단계 전체를 생략하고 Phase 1의 결과만 사용한다.

**여유 자유도(redundancy)에 대한 다중 시드 재시도**: 위치만 제약된 IK는 해가 유일하지 않아(theta1/theta2 조합에 따라 같은 tip 위치에 도달하는 여러 branch 존재), 단일 시드(현재 관절값)로 수렴한 해가 마침 장애물과 충돌하는 branch일 수 있다. 이를 해결하기 위해 최대 60개의 구조화된 시드를 우선순위 순으로 시도한다: ① 현재 q, ② roll을 전체 범위에 걸쳐 스윕하되 벤드=0으로 고정한 9개 시드(장애물을 스치는 큰 벤드 branch를 피하는 데 실험적으로 효과적), ③ 현재 q 주변 가우시안 노이즈 20개, ④ 관절 범위 전체에서 균일 난수 30개. 각 후보 해에 대해 충돌 모델로 검증하여 최초로 충돌-free인 해를 채택한다.

## 3. 충돌 모델링 (Collision Model)

각 강체 링크는 오프라인에서(실제 메쉬로부터) 피팅된 두 볼록 프리미티브 중 하나로 근사된다: 캡슐(선분+반지름, 길쭉한 부품용) 또는 방향성 박스(평평/넓은 부품용 — 캡슐 하나로는 최대 단면을 과대추정하게 됨).

하나의 관절값 $q$에 대해 세 종류의 독립적 충돌 체크를 합성한다:
1. **자기충돌(self-collision)**: 전체 링크 쌍(약 17개 링크, $O(n^2)$)에 대해, 기구학적으로 인접한 쌍과 사전 정의된 무시 목록(마운트 구조상 항상 맞닿는 쌍)을 제외하고 검사.
2. **GO2 몸체충돌**: 팔 링크 vs. GO2 몸체 프록시(몸통 박스 + 머리 캡슐 2개 + 다리 12개 세그먼트, 다리는 실시간 12-값 관절벡터로 순기구학 계산).
3. **환경(정적 장애물) 충돌**: 팔 링크 vs. 월드좌표 방향성 박스 집합(예: 구멍 뚫린 벽을 4개의 축정렬 "액자형" 바(bar)로 분해).

`check_configuration`은 세 체크 중 최소 clearance(가장 심각한 위반)를 반환하며, 어떤 링크 쌍에서 발생했는지도 함께 반환해 진단에 사용한다.

**거리 계산 프리미티브** (모두 근사 없는 정확한 계산):
- **캡슐-캡슐**: 두 선분 간 최단거리(Ericson의 closest-point 알고리즘, 선형시스템의 닫힌형 해 + clamping)에서 두 반지름을 뺀 값.
- **캡슐-박스(선분-박스)**: $t\mapsto \text{dist}(a+t(b-a),\ \text{box})$ 는 $t\in[0,1]$에 대해 볼록함수임(볼록집합까지의 거리함수는 볼록이고, 아핀 재매개변수화는 볼록성을 보존)이 보장되므로, **황금분할 탐색(golden-section search)**으로 전역 최솟값에 (부동소수점 정밀도까지) 정확히 수렴한다. 반복 횟수는 20회로 튜닝했는데, 황금비의 반복당 수축률($\approx0.618$)을 고려하면 1m 길이 선분에서도 서브-0.1mm 정밀도를 보장한다 — 실제 사용하는 clearance 허용오차(cm 단위)보다 훨씬 정밀하다.
- **박스-박스**: **분리축 정리(SAT)** — 두 박스 각각의 3개 면법선 + 두 박스 모서리 방향의 9개 외적, 총 15개 후보 분리축을 검사. 어떤 축이 두 박스의 투영 구간을 분리하면 그 축에서의 gap이 (항상 과소평가만 하는, 즉 안전한 방향의) 표면간 거리 하한이 되고, 분리축이 하나도 없으면 침투 상태로 판단해 가장 덜 음수인 축의 값을 최소 이동거리(MTD) 근사치로 사용한다.

## 4. 전역 경로 탐색: RRT-Connect

Task-space가 아닌 **관절공간**에서 직접 계획한다 — 자유도가 4개뿐이고 hard box constraint가 있어 균일 샘플링 비용이 낮고, 샘플마다 IK를 풀 필요가 없기 때문이다. 관절 범위는 내부적으로 단위 초입방체 $[0,1]^4$로 정규화되므로, step size/충돌체크 해상도 파라미터는 물리 단위가 아니라 "전체 관절 범위 대비 비율"이다(레버가 큰 벤드 축은 unit-space의 작은 스텝도 tip 기준 수 cm 이동에 대응하므로 이 구분이 중요).

표준 양방향 RRT-Connect: 시작/목표에서 각각 트리를 키운다. 매 반복마다 (확률 goal_bias=0.1로 상대 트리 루트를 타겟, 나머지는 균일 랜덤 샘플) 활성 트리를 한 스텝(step_size) 확장하되 **구간 전체를 해상도(collision_check_resolution) 간격으로 촘촘히 샘플링**해 충돌 검증(끝점만이 아님 — 얇은 장애물을 스텝이 건너뛰는 것을 방지)하고, 확장에 성공하면 반대쪽 트리를 새 노드까지 그리디하게 반복 확장(EXTEND의 반복 = CONNECT)한다. 두 트리가 만나면 각 트리의 루트-노드 경로를 이어붙여 해를 반환한다. 매 반복마다 두 트리의 능동/수동 역할을 교대해 균형 있게 성장시킨다. 종료 조건: 연결 성공 / 시작·목표 자체가 충돌 상태 / 최대 반복 초과.

## 5. 경로 후처리

1. **랜덤 shortcut**: 경로 위에서 임의의 두 waypoint를 뽑아, 그 사이를 관절공간 직선으로 대체해도 (margin을 둔) 충돌-free이면 그 사이 구간을 통째로 삭제 — RRT 특유의 지그재그를 정리한다.
2. **Clearance maximization**: 실제 gradient 기반 최적화가 아니라 반복적 local hill-climbing이다. 시작/목표(각각 현재 실제 pose와 IK로 풀린 실제 목표이므로 자유변수가 아님)를 제외한 각 내부 waypoint에 대해 여러 랜덤 관절공간 섭동을 시도하고, (a) 자신의 clearance가 개선되고 (b) 양옆 세그먼트가 여전히 유효할 때만 채택한다. 이미 충분한 clearance를 가진 점은 건너뛰고, 한 라운드 전체가 개선을 만들지 못하면 조기 종료한다(게이트 없는 버전은 실측 90초가 걸려 실시간 사용이 불가능했음). RRT+shortcut만으로는 좁은 통로(벽 구멍 등)를 "간신히" 통과하는 경로(clearance≈0)가 나올 수 있는데, 이 단계로 여유를 확보한다.
3. **재-shortcut**: clearance maximization은 각 waypoint를 독립적으로 움직여 전체 경로 형태를 고려하지 않으므로 지그재그가 재발할 수 있다. 동일한 margin 조건으로 shortcut을 한 번 더 적용해 clearance를 유지한 채 경로 형태를 다시 정리한다.

## 6. 시간 파라미터화 및 실시간 스트리밍 실행

각 구간의 소요시간은 "4개 관절 중 자신의 정격 최대 속도로 그 구간을 이동하는 데 가장 오래 걸리는 관절"의 시간으로 설정한다(모든 관절이 동시 도착한다고 가정 — 구간 내 가감속 성형은 수신측 서보의 자체 프로파일에 위임). 이 구간별 시간표에 따라 고정 스트리밍 주기로 재샘플링해 tick당 관절 명령 시퀀스를 만든다.

실행 중에는 tick마다 참조값을 1칸씩 전진시키지 않고, **실측된 시뮬레이션시간/실시간 비율**로 스케일링해서 전진시킨다 — 그렇지 않으면 실행 환경이 실시간보다 느리게 돌 때(렌더링/물리 연산 부하) 명령 참조가 몇 초 안에 이미 최종 목표까지 다 지나가버리고, 실제로 느리게 움직이는 시스템은 중간(충돌회피용) waypoint 근처에 가볼 기회조차 없이 그냥 최종 목표를 향한 직선에 가까운 궤적을 그리게 된다 — 계획 단계에서 확인한 충돌회피가 실행 단계에서 무의미해지는 문제다. 동일한 실측 비율로 "멈춘 waypoint" 안전 타임아웃(정격 도착시간을 일정 배수/여유시간 초과 시 강제 클리어)도 같이 스케일링해, 안전장치가 환경에 맞는 공정한 기회를 주기 전에 발동하지 않도록 한다. 실제 tip 위치 피드백에 의한 "도달 확인"이 항상 주된 신호이며, 타임아웃은 최후의 안전장치일 뿐이다.

## 7. 성능 최적화 (Ablation)

동일 시나리오(벽 통과, 원시 waypoint 약 37개) 기준 전체 plan/shortcut/clearance-maximization 파이프라인 소요시간:

| 단계 | 소요시간 | 조치 |
|---|---|---|
| Baseline | ~80s | - |
| 1 | ~65s | 충돌 체크 순서를 self-collision→environment에서 environment→self-collision으로 변경 (실패가 결정되는 값싼 체크를 먼저 수행해 조기 종료) |
| 2 | ~52s | 박스-거리 golden-section 반복횟수 40→20 (여전히 서브-0.1mm 정밀도) |
| 3 | ~37s | 박스-박스 SAT의 15축 루프를 numpy 배치 연산으로 벡터화 |
| 4 | ~16s | (2),(3)의 numpy 연산을 순수 파이썬 스칼라 연산으로 재작성 — 3~15개 원소짜리 배열에서는 numpy 호출 오버헤드가 실제 연산량을 압도한다는 재프로파일링 결과에 따름 |
| 5 | ~9s | GO2 몸체충돌(몸통+머리+다리 12개, 총 15개 형상)을 그 순간의 다리 관절값 스냅샷 기준 **단일 병합 박스**로 대체 (다리는 실제로 움직이므로 매 plan 호출마다 그 시점 기준 재계산 — 다리 사이 빈 공간을 보수적으로 "막힘"으로 처리하는 트레이드오프 수반) |
| 6 | ~7s | SAT 계산의 잔여 함수호출/제너레이터 오버헤드 제거(완전 인라인화) |

원본 대비 약 11배 단축이며, 매 단계마다 기존 회귀 테스트 스위트로 충돌 검사 정확도에 변화가 없음을 검증했다. 참고로 시뮬레이터의 디버그 시각화(충돌 지오메트리 오버레이)도 5번 최적화에 맞춰 동일한 단일 병합 박스를 그리도록 수정하여, 화면에 보이는 것과 실제 계획 단계에서 체크되는 형상이 항상 일치하도록 했다.
